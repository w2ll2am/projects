# Archive — what left the box, and what it costs to lose the rest

The VM and `/mnt/filesystem-m9` were wiped on **2026-09-02**. Everything needed
to regenerate every quoted result was pulled to a **local archive** first.

```
~/mats-archive/            (~18.6 GB)
```

This file records what is in it, what is NOT, and what each loss would cost.
Pair it with `CONTENTS.md`, which describes the same artefacts by role.

---

## What was rescued

| dir | size | regenerable? | why it was taken |
|---|---|---|---|
| `data/sdf/` | **401 MB**, 83 files | ❌ **NO** | The corpora. Generated by sampled LLM calls at $85.19; **a rerun produces different documents**. `GA_DS_v1` / `GS_DA_v1` are what every recorded result trained on |
| `results/` | **818 MB** | ⚠️ expensive | All 28 rollout shards + `.summary.json` + valence + `reproduce_check.json`. `14_reproduce_results.py` reads these; without them **no quoted number can be re-derived** |
| `ckpt/` | ~17 GB | ✅ deterministic | 6 adapters × 4 dose checkpoints. Retrainable from the frozen corpora at fixed seed, ~80 min GPU each |
| `logs/` | 9.7 MB | ❌ | Raw run logs. The repo's `results/logs/` holds the distilled 1.1 MB version; this is the unabridged source |
| `run_scripts/` | 204 KB | ❌ | Every orchestration script as it actually ran |
| `_rescue/` | 98 KB | ❌ | 52 stray `/tmp` scripts, **`bash_history.txt`** (the literal command sequence), pip freezes, `nvidia-smi -q` |
| `figures_k30/`, `wandb/` | 4.5 MB | ✅ | Figures and training curves |
| `env.backup` | 4 KB | — | ⚠️ **contains `NEBIUS_API_KEY` in plaintext — ROTATE IT** |

## What was NOT rescued, deliberately

- **Model weights (52 GB)** — `Qwen/Qwen3.5-4B` and `Qwen3.5-27B` are public on
  the Hub. Re-download; don't archive.
- **`.venv` / `.venv-verl`** — rebuild from `evidence/pip_freeze_{main,verl}.txt`,
  now in this repo. The verl venv is kept separate **because its pins downgrade
  vLLM**; do not merge them.
- **Qwen3.5-9B** — the cache dir looked populated but held **0 weight shards**,
  config metadata only. It was never actually downloaded.

## The one gap that cannot be closed

The **k=5 false-positive simulation** (15.7–17.0%) that justifies using the
cluster-t interval. Its code was never committed and no output survives — see
the PROVENANCE note in `FINDINGS.md` and `src/metrics.py`. Wiping the box does
not make this worse; it was already gone.

## Verified sufficient

Run **off the box**, against `~/mats-archive` alone, on a laptop venv holding
only pandas/numpy/scipy/pyarrow:

```
64 checks: 64 match, 0 MISMATCH, 0 unverifiable      exit 0
```

Full output: `evidence/reproduce_from_archive_20260902.txt`. Every Gate 1,
Gate 2, belief-recall, corpus and calibration number in `FINDINGS.md` was
recomputed from the archived shards. **The box is not needed for any quoted
result.** Two checks initially failed on stale constants — `recall_steps_d100`
still carried the pooled 0.627/0.573 rather than the corrected 0.665/0.622 —
which is exactly the regression this script exists to catch. Fixed.

## Restoring

```bash
export EXP_ROOT=/path/to/new/box/gcvl
rsync -a ~/mats-archive/{data,results,ckpt,logs,run_scripts}/ $EXP_ROOT/
export HF_HOME=/path/to/hf ; huggingface-cli download Qwen/Qwen3.5-4B
python -m venv $EXP_ROOT/.venv && $EXP_ROOT/.venv/bin/pip install -r <(...)  # see pip_freeze_main.txt
python scripts/14_reproduce_results.py            # must exit 0
```

`14_reproduce_results.py` exiting non-zero means the archive is incomplete —
it recomputes every quoted number from the shards and fails on mismatch.

⚠️ **Adapter weights live in `checkpoint-*/`, not the run root.** Passing the
root to `--adapter` kills vLLM with a bare `EngineDeadError`.
